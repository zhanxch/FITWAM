解释与风险

  • B 不应在 6500 判断成败。 6500 是 38/100，但 11000 和 12240 已到 81/100、82/100。
  • C 的问题更像后期退化。 6500 有 74/100，说明 structured checkpoint 在早中期可以工作；final 4/100 不应简单解释成部署链路完全坏。
  • 保留 rollout 权重。 关键是 checkpoints/weights/step_xxxxxx.pt；DeepSpeed optimizer state 是 resume 用的大文件，不等于 rollout 权重。
  • 合并口径。 B 的 100 条合并包含 legacy summary-only 的 seed 0-24 和新增 full artifact 的 seed 25-99；报告会明确标注 artifact 覆盖范围。

下一步

  1. 可选补 C step_006000，用来确认 C 的 6500 高点是不是稳定窗口。
  2. 诊断 C final 退化：训练 loss/val、checkpoint 差异、metadata/outcome head 权重、deploy 输入一致性。
  3. 同步 eval fallback、结果摘要、轻量 artifact manifest 到 GitHub。

名词速查

Text-failure把失败 outcome 拼到 task text；失败样本只用 video loss。
Structured-failure把 outcome/failure 当成结构化 flag 或 metadata。
Checkpoint weights用于 rollout/deploy 的 .pt 权重，应保留关键节点。
DeepSpeed state训练 resume 用的 optimizer/model shard 状态，通常很大。
