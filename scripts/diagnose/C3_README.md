## Goal

Determine whether leaving the rot6d dimensions UN-normalized (identity) while
keeping z-score for xyz/hand fixes the rot6d manifold warp identified in A2.
This is the **second-highest-priority** hypothesis per the analysis plan.

## Root cause recap (from A2)

The baseline applies a single per-dimension z-score normalizer to the whole
58-dim action. Because the rot6d dims have non-uniform ranges (0.47 to 1.32)
and different mean/std offsets, the normalizer scales the two rows of the
rotation matrix by **different factors** and shifts them by **different
offsets**. A perfectly orthonormal rotation (orthonormality error ~1e-7 in raw
space) becomes **highly non-orthonormal** in normalized space (error ~1.79),
with row norms ~1.14 and row dot product ~0.69. The model must therefore fit
targets on a warped manifold, and diffusion sampling errors get amplified by
the 2.79x per-dim scale mismatch when denormalized.

GR00T avoids this by using per-modality `temporal_meanstd` normalization for
rot6d. DexJoCo (sim) uses rotvec (3-dim), which has no orthonormality
constraint, so the warp does not affect the sim pipeline.

## The fix

Added an optional `skip_dims` parameter to the normalizer that makes selected
dimensions **identity** (scale=1, offset=0) so they pass through un-normalized.
rot6d values already live in [-1,1] by construction, so they need no rescaling.

### Code changes

| File | Change |
|---|---|
| `src/fastwam/datasets/lerobot/utils/normalizer.py` | `SingleFieldLinearNormalizer(skip_dims=...)` sets scale=1, offset=0 for listed dims; `LinearNormalizer(skip_dims=...)` passes per-key skip lists |
| `src/fastwam/datasets/lerobot/processors/fastwam_processor.py` | `FastWAMProcessor.norm_skip_dims` config field, forwarded to `LinearNormalizer` |

These changes are **backward compatible**: `skip_dims` defaults to None, so
existing configs are unaffected.

### Config / script changes

| File | Purpose |
|---|---|
| `configs/data/spray_water_rot6d_rosbag_ts_filter_skip_rot6d.yaml` | Data config: adds `norm_skip_dims` for rot6d (left 3:9, right 12:18) |

### Verification

```bash
python scripts/diagnose/test_skip_dims_normalizer.py
```
Output confirms:
- skipped rot6d dims: scale=1.0, offset=0.0 (identity)
- non-skipped dims: scale != 1 (still z-score normalized)
- round-trip identity (error ~0)
- orthonormality preserved after forward on skipped rot6d (error = 0.0)

## Run the experiment

### 1. Train (A/B against baseline)

```bash
# Smoke test:
bash scripts/train_spray_water_rot6d_skip_rot6d.sh \
    max_steps=200 save_every=100 eval_every=100

# Full run:
bash scripts/train_spray_water_rot6d_skip_rot6d.sh
```

The run lands under
`runs/spray_water_rot6d_rosbag_ts_filter_uncond_3cam_384_1e-4_skip_rot6d/<ts>/`.

### 2. Deploy

Use the **same** server/client scripts. The server loads the new
`dataset_stats.json` (generated by the new data config) and the normalizer
will apply skip_dims automatically — no server code change needed.

### 3. Compare open-loop + closed-loop

- Open-loop: `eval/action_l1` should be comparable to or better than baseline.
  Note action_l1 is computed in the (now less-warped) normalized space, so a
  change here is informative.
- Closed-loop: the real-robot rollout is the real test. If the left-arm
  oscillation/stuck behavior improves and grasp holds, H2 is confirmed.

## Verdict criteria (from the plan)

- If real-robot rollout improves (less oscillation, grasp holds) -> **H2
  confirmed**: the rot6d warp was a root cause. Fix = always use skip_dims (or
  per-modality normalization) for rot6d dimensions.
- If no improvement -> H2 is not the primary cause; revisit H1 by training a
  `proprio_dim: null` variant (偏离官方默认，仅作诊断) to see if proprio
  removal hurts.

## Note on H1 + H2 combination

基线已走官方默认带 `proprio_dim=58`（自动继承），C3 task config 同样带
proprio=58，所以 **C3 本身就是"proprio + rot6d 不归一化"的组合**，无需再合并。
C3 即对应 GR00T 的做法（state 条件 + 分模态 rot6d 归一化），是当前最可能
关闭 sim-vs-real 差距的配置。
